# Checkpoints do Lycan

Um checkpoint = uma entrega pequena + commit publicado + estado de retomada. Publicar cada fonte antes de produzir derivados. Nunca acumular várias ações inéditas na mesma execução.

| Checkpoint | Entrega | Estado |
|---|---|---|
| CP0 | Preservar Walk anexado, sem alterar bytes | Publicado |
| CP1 | Recuperar turnaround, Idle, prompts, contrato e inventário | Recuperado; aprovação visual pendente |
| CP2 | Recortes documentados e GIFs por direção para revisão | Previews técnicos; aprovação temporal pendente |
| CP3 | Revisar somente Walk E: proporções, apoios, loop e câmera | Próxima etapa |
| CP4 | Corrigir e validar uma direção por checkpoint | Pendente |
| CP5 | Revisar Idle e identidade; uma entrega por checkpoint | Pendente |
| CP6 | Claw E, depois Bite E, Howl E, Hit E, Death E e Run E | Um piloto por checkpoint, pendente |
| CP7 | Expandir cada ação validada para uma direção por checkpoint | Pendente |
| CP8 | Alpha, pivôs, eventos, atlas e integração | Pendente |

Salvar fonte, prompt disponível, manifesto, preview, defeitos e próximo passo em cada commit. Se houver interrupção, ler AI_STATE.md e verificar main antes de retomar. Não regenerar arte já preservada sem motivo documentado. Gerado/publicado não significa aprovado.
